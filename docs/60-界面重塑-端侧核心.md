## 0. 为什么要重塑

D3 是在「远程客户端」定位下写的：它的信息架构把「连接一个 Host」当成前提，
于是"添加 Host / 配对 / 隧道 / 连接诊断"占据了大量一等位置，而**"本机核心"这件事在界面里根本不存在**。

目标改成「应用本体自足运行 DSH 核心」之后（D6 §0），界面必须回答一批**原来不存在的问题**：

| 新问题 | 原来界面里的答案 |
|---|---|
| 我的核心是什么版本？装在哪？ | 没有这个概念 |
| 第一次启动要等多久？在做什么？ | 没有这个概念 |
| 想换一版 / 换坏了怎么回滚？ | 没有这个概念 |
| 为什么终端/图片功能没有？（原生件没加载） | 没有这个概念 |
| 哪些插件能装、哪些不能？为什么？ | 插件页是**只读清单**，且不区分纯 JS / 原生 |
| 核心起不来时，我该看什么？ | 诊断页的五项判定全部围绕**远程连接**（端点/TLS/认证/协议/Host） |

**结论**：不是"加一个页面"，而是**把一级信息架构从"连接中心"改成"会话 + 核心"双中心**，
并把远程接入从主流程降级为可选能力。

## 1. 新信息架构

```
一级导航（5 项，手机底部标签栏上限）
├── 待决      审批 / 提问聚合（不变）
├── 会话      会话列表 → 轨迹 → 输入区（不变，但数据源改为本地核心）
├── 工作区    文件树 / 预览 / 投喂（不变）
├── 核心      ★ 新增：端侧 DSH 核心的运行、版本、插件、诊断
└── 设置      通用 / 模型 / 凭据 / 插件 / 高级（远程 Host 移入此处）
```

「核心」与「设置」相邻但不合并：**核心是"能力与运行"，设置是"偏好与凭据"**。
把核心状态塞进设置页会造成"设置页里藏了一个正在运行的服务器"这种难以理解的结构。

## 2. 「核心」页规格（D6 §2/§6 的界面落点）

四个分区，自上而下：

| 分区 | 内容 | 关键纪律 |
|---|---|---|
| **状态卡** | 阶段徽标（未接线/未安装/解包中/启动中/就绪/降级/失败）+ 当前版本 + profile 名 + 一句话结论 + 补充说明 + 动作行（启动/重启/停止/回滚/导入核心包/导出诊断） | **不可用的动作必须把原因显示在按钮下方**；禁止静默禁用、禁止点了没反应 |
| **运行时** | Node 版本 / zlib zstd 能力 / JIT 状态 / 原生件（koffi、node-pty、sharp）加载结果 / 监听地址 | 未探测的写「未探测」**并给出探测条件**；不编值 |
| **核心版本** | 已安装版本列表（当前 / 上一版 / 已安装 徽标、切换入口）+ 空态说明 | 「上一版」必须始终可见（回滚目标）；当前版本不可被切成自己 |
| **插件** | 纯 JS 插件（可安装/停用）与含原生 `.node` 的插件（需随应用发版）**分两类呈现**，各自说明原因 | 见 D6 §6.2 的硬约束：热更新下载的 `.so` 会被系统拦截 |

**首次启动流程**（替代原来的"添加 Host"）：

```
启动 → 检查 <files>/dsh/cores 是否已有版本
  ├─ 有 → 直接起核心 → 健康检查 → 就绪 → 会话页可用
  └─ 无 → 核心页显示「正在首次解包」（带进度与预计时间）
          → 解包 → 校验签名/元数据 → 起核心 → 健康检查 → 就绪
```

**长任务要可见**：解包 2.5 万文件 / 约 63 MB 压缩包，必须给进度而不是转圈。

## 3. 「去掉无用功能」清单

这里的"无用"是**相对新目标**而言；删除或降级都必须写清去向，不允许静默消失。

| # | 原功能 | 新定位 | 理由 |
|---|---|---|---|
| 1 | 「添加 Host」作为一等入口（ConnectPane 首屏可达） | **降级**到「设置 → 高级 → 远程 Host」 | 本机核心存在时，"必须填一个地址"是错误的默认路径 |
| 2 | 启动参数注入地址与令牌（`dshLaunch*`） | **保留但改语义**：默认由本地核心自动注入；显式参数仅用于调试/远程 | 界面零手填仍成立，且来源从"外部 Host"变成"本机核心" |
| 3 | hostkit 配对 / 隧道 / 二维码 / 设备授权 | **降级**到「高级」，并标注"用于连接**远程** Host 的可选能力" | 端侧自足后不需要隧道；留着但不能占据主流程 |
| 4 | 诊断页的 TLS / cookie 授权 / 远程 Host 判定 | **按模式分流**：本地核心模式下显示"运行时/核心/协议"三项；远程模式下才显示远程专属项 | 否则本地模式下会出现一堆"不适用"的判定项，制造噪音与误判 |
| 5 | 「POC 协议验证」页（首屏右上角入口） | **收进核心页的"导出诊断"** | 它是验收工具，不是产品功能 |
| 6 | 插件页签的**只读清单** | **升级为可操作**，且区分纯 JS / 原生 | 「支持各类插件」是目标的一部分，只读等于没做 |
| 7 | 会话页在"未连接"时的文案（"请添加 Host"） | 改为按核心阶段分档：未安装/解包中/启动中/失败，各自给下一步 | 新架构下"没连上"最常见的原因是**本机核心还没起来**，而不是地址填错 |

## 5. 纪律（沿用并加强 D3 §4）

1. **没有桩数据**：核心状态、版本、运行时事实、插件清单全部来自真实来源；未接线就显示"未接线"。
2. **不可用必须说原因**：按钮禁用时把原因写在旁边（`CoreActionSpec.reason`）。
3. **未探测 ≠ 未知**：写「未探测」+ 探测条件（`unknownFact(label, howToProbe)`）。
4. **判据进纯函数**：`buildCoreView` / `decideActivation` / `decideRollback` / `evictionCandidates` /
   `classifyPlugin` 都是纯函数，单测覆盖"该显示什么、能不能点"，而不是靠肉眼验收。
5. **长任务可见**：解包、启动、健康检查都要有进度或阶段文案。
