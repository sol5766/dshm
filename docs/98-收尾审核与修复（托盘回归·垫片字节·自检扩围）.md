## 4. 教训

1. **幂等守卫的顺序本身就是正确性的一部分**：把"清理"放在"早退"之前，看着更保险，实际是"每次调用都先毁掉再走人"。
2. **两个方向要对齐**：请求方向支持的 body 形态，响应方向也必须支持——否则故障表现成"200 但内容错"，比显式失败难查得多。
3. **兜底不要静默改内容**：无法识别就抛（标准 Fetch 语义），把错误留给调用方，而不是把坏数据交给下游。
4. **临时证据目录要优先清理**：`.gate-logs/`、`.review-*`、`.review-shots/` 都**未被 `.gitignore` 覆盖**，`git add -A` 会一次暂存 61 项（含约 52 项证据）⇒ 收尾顺序应是**先清证据、再提交**，并且提交一律用**显式路径**。
