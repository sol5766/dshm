# 独立审查提示词（三路，各自对抗性）

本文件是我为"最后审核"写的校验提示词。三路互相独立、各有专属怀疑方向，
目的是**证伪**我自己的改动，而不是复述我的说法。

---

## 路 A：正确性审查（语音 + 启动 + 图标）

**角色**：你是独立审查者，任务是**找出这轮改动中的缺陷**。不要复述改动说明，
不要称赞，只报告你能**用证据证明**的问题。

**背景**：这是一个 HarmonyOS 应用（包名 `com.dshm.dshclient`），把 dsh（DeepSeek Harness）
的 Node 运行时装进 HAP。工作目录 `D:\desktop\temp\desktop.ohos.arm64`。

本轮改动涉及：
1. **语音**：SenseVoice 离线识别，模型**不再内置**（原 228MB 在 rawfile），改为启动后从
   GitCode 在线下载 + sha256 校验。ArkTS 侧 `SenseVoiceRecognizer.ets` 从沙箱**文件路径**
   加载模型（**不传 resourceManager**）。
2. **启动体验**：白屏自愈（404 → 自动重试）；进度条匀速化。
3. **图标**：APP 图标换成"官方白鲸 + HM/OS 角标"；**启动画面资源必须保持原版**。

**必须逐条核验并给出证据（文件:行号 或 命令输出）**：

| # | 核验项 | 判据 |
|---|---|---|
| A1 | HAP 内**没有**内置语音模型 | `rawfile/sensevoice/` 条目数 = 0 |
| A2 | HAP 内**有**语音库与下载器 | `libs/arm64-v8a/lib{sherpa_onnx,onnxruntime,sherpa-onnx-c-api}.so` 与核心 zip 里的 `speech-models/index.js` 都在 |
| A3 | 启动资源是**原版** | HAP 内 `startIcon.png`/`logo_dark.png` 的 sha256 = `5a1a1ac3885f1008…`（14.9KB），**不是**我生成的 28–30KB 版本 |
| A4 | APP 图标是**新版** | HAP 内 `foreground.png` 含 HM/OS 角标 |
| A5 | 进度条是**匀速**曲线 | 读 `entry/src/main/ets/pages/WebApp.ets` 的 ticker：应是 `elapsed/1000*RATE` 线性，**不是** `exp()` |
| A6 | 进度表**不会**在进 LOADING 时被杀 | `enterLoading()` 里**没有** `stopLoadTicker()` |
| A7 | 启动页**只在首次加载**显示 | 条件含 `!this.everReady`（否则应用内跳转会闪启动页）|
| A8 | 白屏自愈**不会**把内部重试暴露给用户 | `fail()` 在有重试预算时置 `LOADING` 而非 `ERROR` |

**最高优先级怀疑（请重点攻）**：
- 有没有**残留的调试代码/插桩**？（搜 `SP_TIMING`、`spMark`、`__pycache__`、`.bak`）
- 有没有**同一常量两处定义**（重复定义在 ArkTS 里会编译错，但语义重复更难发现）？
- `everReady` 是**只增不减**的吗？有没有被错误重置的路径？
- 如果宿主**第一次就失败**（真失败，非竞态），用户能否看到错误页与「重试」按钮？

**输出格式**：
```
## 结论
（一句话：通过 / 有 N 个问题）

## 问题清单
| 严重度 | 位置 | 问题 | 证据 | 建议 |
（严重度：阻断 / 高 / 中 / 低；每条必须有证据）

## 无法验证的项
（如实列出你没能确认的，不要猜）
```

## 路 B：一致性与残留审查（改名 + 文档）

**角色**：独立审查者，任务是**找出改名不彻底或文档与代码不符之处**。只报有证据的。

**背景**：本项目本轮做了 **HDSH → DSHM** 全局改名（213 种标识符 / 1244 处 / 115 文件 + 9 个文件改名）。

**必须核验**：

| # | 核验项 | 判据 |
|---|---|---|
| B1 | 源码里残留的 `hdsh` 是否**全部**属于"应保留"的 | 只允许：`com.hnmrxz.hdsh`（历史 bundleName，讲历史）、`hdsh_port_ppt169_*`（外部 PPT 工程名） |
| B2 | `dshhost` / `libdshhost.so` **未被误改** | 它是 dsh+host，不是 HDSH。搜 `dshhost` 应仍有大量命中 |
| B3 | 文档里的"当前形态"描述与代码一致 | 尤其 `docs/brand/README.md`、`README.md`、`docs/50`、`docs/70` |
| B4 | 门禁脚本里的**断言方向**是否合理 | 已知曾有一条自相矛盾断言（`includes('/dshm-python/')` 与 `!includes('dshm-python')` 同存），确认它已修正且**没有同类**存在 |
| B5 | pack-core 的幂等标记是否**新旧都认** | 核心树里若有旧标记（`HDSH_*`），只认新名会导致重复打补丁而 `die` |

**最高优先级怀疑**：
- 文档里有没有**描述"当前实现"却与实际代码不符**的地方？（比残留改名更危险，会误导后续）
- `docs/brand/README.md` 说"新图标只用于 APP icon、启动画面用原版"——**代码是否真的如此**？
- `tools/make-icon.py` 是否**真的不写** `startIcon.png`/`logo_dark.png`？

**输出格式**：同上（结论 / 问题清单 / 无法验证的项）。

## 路 C：可维护性与工程纪律审查

**角色**：独立审查者，任务是找出**会坑到后来人**的设计问题。只报有证据的。

**本项目有强制纪律（见 `AGENTS.md`）**，请据此评判：
1. 改动前跑基线、改动后跑同一批，任何 ok→fail 必须当场修
2. 临时实验必须在同一次改动内还原
3. 一次性排查脚本用完即删，不留 `tools/`
4. **绝对禁止**删设备用户数据（只允许 `hdc install -r`）

**必须核验**：

| # | 核验项 |
|---|---|
| C1 | 我加的两个**自检**是否真的能拦住错误（`make-icon.py` 的内腔透明检查、旋转触边检查）|
| C2 | 有没有**注释与代码不符**（注释说 A、代码做 B）—— 这是最难查也最坑的 |
| C3 | `tools/make-brand-assets.mjs` 的**废弃守卫**是否有效（应拒绝执行并指向新脚本）|
| C4 | 有没有**只在一处生效**的常量（改了这处忘了那处）|
| C5 | 文档里"踩过的坑"章节是否与实际代码注释**互相印证**，有无矛盾 |

**最高优先级怀疑**：
- `make-icon.py` 里有没有**重复/互相矛盾的坐标计算**？（我自己发现过两次：
  "行内偏移减了两次"、"块高没随行距重算"）
- 我在 `docs/` 里写的"已修"条目，**代码里是否真的修了**？（文档不能只是承诺）

**输出格式**：同上（结论 / 问题清单 / 无法验证的项）。
