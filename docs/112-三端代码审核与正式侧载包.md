## 1. 三端审核：11 处分档点逐条判

### 1.1 方法（先把判据定下来，避免"看着像"）

**唯一分档源**：`platform/src/main/ets/system/DeviceFacts.ets` 的 `formOf()` ——
`phone` ⇒ 手机、`tablet` ⇒ 平板、`2in1` / `2in1_foldable` / `desktop` ⇒ 桌面（含鸿蒙 PC）、
其余（`default` 等）⇒ `unknown`。手持档的收口函数是 `FilePicker.ets:isHandheldForm()`，
**只在 form 为 phone / tablet 时返回 true，读形态失败时返回 false（退到非手持）**。

对每一处分支问三个问题，三个都成立才判"成立"：
(a) **判据与设备事实同源**（不从形态反推物理输入设备这类"猜"）；
(b) **失败方向保守**（读不到事实时退到哪一端？必须是"不误伤已验收的那一端"）；
(c) **有兜底**（门禁或真机读数；没有读数的分支必须写明"未验证"）。

### 1.3 逐端结论

- **PC / 2in1（鸿蒙 PC，`2in1` / API 26）**：全部手持档分支对它**逐一早退**（`isHandheldForm()` 为 false；
  朝向、授权恢复、进程内通道全部不进）。专门守 PC 的两条门禁在跑：`check-decor-button-mode`（顶栏底色 ↔ 三键配色接线）、
  `check-profile-pnpm-bridge` / `check-market-bridge` 的"假壳能跑 ⇒ 不接管"对照臂 ⇒ **本轮改动对 PC 的影响面 = 0**。
- **手机（`phone`）**：手持档三条（授持久化 / 朝向 / 进程内通道）全部生效；已知边界两条如实保留：
  ① bash 与随包自签名 ELF 被 MAC 拒绝（`ash=denied`）⇒ `bash` 工具通道不可用；
  ② 系统 PreviewKit 在 phone 上无 syscap ⇒ "用系统打开"会弹"未受理"（侧栏内联预览不受影响）。
- **平板（`tablet` / API 24 目标）**：分档与手机**同一条**（`isHandheldForm()` 覆盖 phone + tablet），
  所以手机档验过的三条路径逻辑上同样适用；差异只在断点（横屏进 TRIPLE）与 bash 档位**未单独实测**。
  ⇒ **本端唯一"未验证"项是 bash/ELF 档位**，已如实登记，不当作结论。

### 4.2 为什么"正式"仍然用 debug 签名（必须说清楚）

- **签名物料只有一套**：DevEco **调试证书**（`keyAlias=debugKey`）。发布证书只在 AGC 侧，
  换签名会让设备上已装版本**不能 `install -r`**（签名不一致 ⇒ 只能卸载 ⇒ 直接撞上 el2 数据不可逆丢失那条路）。
  故正式件的口径是"**对外分发的 debug 签名侧载包**"，与 `docs/80` 的更新纪律一致。
- **release（`n`）构建会降级功能**：`release` 下 `bash` 探测变成 `denied`（`debug` 为 `ok`），
  原因未查明。所以本包**固定 debug 构建**；若将来要出上架用 `n` 包，必须先查清并修掉这条。

### 4.3 内容新鲜度（为什么不需要重编）

本包是**新构建**（不是上一份的逐字节复用）：`+dshm.13` 改的是核心树里的自带插件 ⇒ 必须重出容器、重编、重签。三条判据：

### 5.3 执行中查出的两个坑（这才是本节的正文）

**坑 1：`matchGlob` 的链式 replace 会自我改写 ⇒ `**&#47;*.d.ts` 只删到一层目录。**
`tools/pack-core.mjs` 的 matchGlob 原来是三步 `String.replace`：①转义正则元字符 →
②把 `**&#47;` 换成"任意层目录前缀" → ③把 `*` 换成 `[^/]*`。**第 ③ 步会把第 ② 步刚注入的
占位符也一起改写**，最终正则退化成"只认一层目录"。实测后果：`**&#47;*.d.ts` 只删到 128 / 7448 个，
容器 zip 只小 0.77 MiB（预期 −24.8 MiB）；而日志里"删除 xx MB"**看不出异常**——`dirSize` 只在
循环前后各测一次，中间少删多少都自洽。**同一条链上的 `**&#47;*.exe` / `*.dll` / `*.pdb` 也一直只删到顶层。**
改法：**单次 replace + 回调**（回调返回值不再被扫描）。修完才发现本题的真正工作量在下面这条。

**坑 2：`**&#47;*.md` 会删掉"看着是文档、实际是运行期资源"的文件。**
- `@deepseek-ai/dsh-skill-badge/lib/index.js`：`const SKILL_BODY_URL = new URL("../assets/dsh-badge.md",
  import.meta.url)`，`get()` 里 `await readFile(SKILL_BODY_URL, "utf8")` —— 这是**内置技能 `dsh-badge`
  的正文**。删掉它，该技能的 provider 直接抛错（不是"少个说明文件"，是**功能坏**）。
- `@deepseek-ai/dsh-experimental-inspector/lib/devtools/` 下 240 个 `.md`（`models/issues_manager/
  descriptions/*.md`、`panels/whats_new/resources/WNDT.md`）由同目录 `resource-manifest.json` 登记，
  是 DevTools 面板内容。

⇒ 加两道保险，代价合计 **0.107 MB / 245 个文件**：
1. `PRUNE_KEEP_BASENAME_PREFIXES`（pack-core 内）：`license|licence|notice|copying|authors|contributors|thirdpartynotices`
   前缀的文件名一律不删 —— 删 `**&#47;*.md` 会把 `LICENSE.md` / `NOTICE.txt` 一起删，**合规问题**；
2. 配方新增 `keepGlobs`（**运行期资源豁免，优先级高于所有 `removeGlobs`**）：`**&#47;assets/**`、`**&#47;devtools/**`。
   已核：这两处目录下**没有**任何 `*.exe/*.dll/*.pdb`（否则也会被豁免留住，那样就不划算了）。
