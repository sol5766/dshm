## 三、视频简介（可直接粘贴）

```
BrewDSH —— 面向 HarmonyOS NEXT 的 DeepSeek Harness 客户端。

把"住在终端里的 AI 编程智能体"变成鸿蒙原生桌面应用：双击图标就能用，
会话管理、插件市场、终端、工作区全部图形化，不需要先打开命令行。

【它是什么】
DeepSeek Harness（dsh）是一个跑在终端里的 AI 编程智能体。BrewDSH 是它的鸿蒙客户端：
运行时用 Harmonybrew 提供的原生 node + dsh（JIT 可用），App 负责图形外壳、会话管理、
插件市场接入，另外内置一份不依赖 Harmonybrew 的 jitless 兜底环境。

【两种运行模式】
· 宿主模式（默认）：自动识别 ~/.harmonybrew/bin/dsh，用 brew 装的 dsh + 原生 node 跑，启动快、插件能力完整
· 内嵌模式：应用自带 Node 运行时，零依赖，未装 Harmonybrew 也能用
两种模式各自维护独立会话库，切换时先干净停掉旧实例再按新模式启动（不抢端口）

【本期演示到的功能】
00:00 开场：它解决什么问题
00:20 启动与首屏（白底黑鲸鱼启动页 → 会话界面）
00:50 会话：多会话、工作区、模型切换
01:30 插件市场：搜索 → 一键安装 → 热加载生效（内置 dshmarket）
02:20 终端：真 pty、Tab 补全、历史、Ctrl-C；触摸端有 Tab/↑/^C 按钮
02:50 运行环境面板：一键装/升级 Harmonybrew 运行时，进度实时可见
03:20 系统集成：托盘图标左键唤回主窗口、关闭窗口后常驻托盘（服务不断）
03:50 双模式切换：宿主 ⇄ 内嵌，先杀旧进程再进新模式
04:20 技术硬骨头（可选看）：沙箱 W^X 只能 jitless、只有 el1 库能 dlopen、
      不能 execv 用户区 ELF 所以 pnpm 走同进程 worker
05:00 结尾与后续计划

【技术要点（给同行）】
· 鸿蒙沙箱禁止创建可执行内存 → 内置 Node 必须 --jitless，用垫片补 Web 全局与 WebAssembly
· 沙箱只允许 dlopen el1 bundle 库目录里的 .so → 原生库必须随 HAP 打进 libs/
· 不能 execv 用户数据区的可执行文件 → pnpm 不能起子进程，改为在 dsh 进程内用 worker
  执行内置 pnpm（这也是插件市场能装插件的前提）
· 系统集成：statusBarManager 托盘图标（左键唤回）+ 关闭窗口隐藏到托盘常驻（DSH 服务不断）

【说明】
· 这是一个个人移植项目，未上架应用市场，安装包需要侧载（hdc install）
· 需要鸿蒙 PC / 2in1 设备（托盘常驻能力为 PC 形态专属）
· 部分受限权限（全盘文件访问等）需要你在系统设置里手动开启，视频里会演示
· 项目开源，仓库地址见评论区置顶

如果对你有帮助，三连支持一下，评论区告诉我你想看的功能。
```
