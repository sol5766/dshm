# DSHM v1.1.0 发布说明

> 本文同时作为 GitHub Release `v1.1.0` 的发布正文（<https://github.com/sol5766/dshm/releases/tag/v1.1.0>）。
> 与之配套的侧载包与校验见 `dist/sideload/`（不入库）。


> 覆盖区间：**2026-09-30 → 2026-10-05**（71 个提交、146 个文件、+24,535 / −3,728 行）。
> 每个条目后附提交号，便于逐条溯源。应用版本：`versionName 1.1.0` / `versionCode 1010000`。

## 一、侧边栏文件预览（本轮最大的用户可见变化）

- **Office 文档改用系统预览窗**（`cadb811`）：doc/docx/ppt/pptx/xls/xlsx/odt/ods/odp 共 **9 项**由插件认领并调系统 PreviewKit；
  `csv/tsv` 等未被认领的格式交回上游内置渲染器。
- **认领范围收窄与纠偏**：插件原认领 19 个后缀（含 ico 等越界项）⇒ 收敛为 Office-only（`1e30b01`、`a04cfac`）。
- **修复「点击文件报 `Failed to fetch`」的真根因**（`1e30b01`）：宿主纯 JS undici 垫片不认 `new Response(FormData)`，
  而客户端在 RPC 结果带附件（如 `readBytes` 的 `Uint8Array`）时会构造 FormData 响应 ⇒ 垫片把它交给桥层 ⇒
  `ERR_INVALID_ARG_TYPE` ⇒ webserver 在 `headersSent` 后 `res.destroy()` ⇒ 客户端只见 `ERR_EMPTY_RESPONSE(-324)`。
  **修复后真机 `readBytes` 的取消数自 149 起零新增**，成功数随点击文件正常增长（见 `docs/97`）。
- 预览 loading 口径改 `text-pages`；并立下「出包必须带 `--place-in-app`」的教训与门禁（`ecd4644`）。
- 撤除先前误判引入的无效补丁 `DSHM_DOC_LOAD_DEDUP`（`152c07e`）。

## 二、托盘与退出（按三条需求重做）

- 应用运行时在状态栏挂图标；**左键单击唤回主窗**；**右键只用系统自带菜单**（不再自建菜单项）（`ab996b8`）。
- 修复托盘的**幂等回归**：同一进程第二次挂载会先摘掉活着的图标再早退 ⇒ 图标永久消失（`5b7d47d`）。
- 删除恒无效的「后台 Ability 兜底摘图标」（跨进程 static 恒 false + SDK 无前台窗口必报 `1010710004`）（`5b7d47d`）。
- 系统「关闭窗口」回到**官方行为 = 退出应用**，不再拦成"最小化到后台"（`ecd4644`、`b25f47f`）。

## 三、窗口与界面

- **修复右上角三键（全屏/最小化/关闭）不可见**（`0d118a9`）：顶栏底色有两条通道、而三键配色只挂在其中一条 ⇒
  深色外观下顶栏变 `#151517`、三键仍是深色图标 ⇒ 黑底黑键。真机像素判据：三键区亮像素 **0 → 114**（见 `docs/99`）。
- 工作区/目录选择器：「成功但有代价」时给出提示；"换路径"经 emitter 上报壳层（`71c8cba`、`1cfd56c`，GitHub issue #3 的 R3）。

## 四、核心树与端侧补丁

- 端侧核心升到 `0.2.1-alpha.1`（兼容契约**连续第四次零漂移**），并按需递增 `+dshm.1`…`+dshm.6`（`000e8d3`）。
- 端侧注入补丁门禁从 13 处扩到 **19 处注入 + 1 处撤除守卫**，并修掉若干"看不见的恒真判据"（`ee92b44`、`16378d9`、`7a03ffb`）。
- 修复 `pack-core` 平台门放行后 `process.report.getReport()` 把冷启动挡住 62 秒的问题（`5f27b18`）。

## 五、宿主（host）能力、稳定性与可诊断性

- jitless 补齐**下沉到 worker**；PTC 换**同进程纯 JS 运行时**；glob 目录锚定（`b4bdcb5`）。
- 文件能力（remove/move/publish + 去 chmod 写入）与四个上游缺陷的构建期补丁（`570cc2a`）。
- undici 垫片补齐具名导出；用户插件行去重（`f6c6684`）；宿主三项缺陷与 jitless 下的网络/终端适配（`5bbfe6b`）。
- **可诊断性大升级**：同步调用环 `SYNC-RING`/`SYNC-WARN`/`SYNC-COUNT` 直接点名"挡住事件循环的那次同步调用"（`fd1e10f`、`6c8c8fe`）；
  心跳线程 `HB` 把"主线程被挡"和"进程被冻住"分开（`86d9ecd`）；V8 CPU 采样点名停顿期间在执行什么（`2e0bf6f`）；
  accept 轨迹与事件循环看门狗（`4f03ddd`）；逐跳 `IN-DONE` 耗时与插件日志时间戳（`433a943`）；诊断默认开启（`8854369`）；
  以及补上"本机 hilog 读不到本应用 ArkTS 输出"的取证缺口：console 落盘 `diag-web-console`（`c7b6798`）。

## 六、门禁与 CI

- 新增 GitHub Actions 门禁流水线 `gates.yml` 与行为准则（`fa2d1ed`）；`.gitattributes` 钉行尾修 Windows 假红（`e11901d`）。
- `check-doc-refs` 新增判据 F（不许对 AGENTS.md/README.md 写行号）并清掉 42 处（`bdebce4`）。
- 新增 `check-fetch-mirror`（出网镜像改写）（`53388f5`）与 `check-decor-button-mode`（顶栏底色 ↔ 三键配色接线，带对照臂）（`0d118a9`）。
- `update-device.ps1` 的"数据保全"判据改为 stat 指纹（`21c1509`），覆盖安装后会自动断言用户数据未减少。

## 七、文档与开源治理

- 新增 `docs/95`（收尾审计台账）、`docs/96`（侧栏预览竞品调研）、`docs/97`（readBytes 空响应根因）、
  `docs/98`（收尾审核与修复）、`docs/99`（右上角三键不可见）；README 面向新读者重写、去机器专有路径；补齐协作与安全治理文件（`3c64244`）。

## 八、升级方式

- 覆盖安装（**不要卸载**，卸载会丢用户数据）：`hdc install -r DSHM-1.1.0-arm64-signed.hap`；
- 同签名的原位升级只替换代码与资源，不动会话/插件/工作区（el2 数据）；
- 安装后可在应用内「设置 → 关于」看到 `1.1.0 (1010000)`。
