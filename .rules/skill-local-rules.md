# 技能：本地规则库与环境事实沉淀

**适用场景**：Agent 在陌生机器、陌生模拟器、不同 DevEco/SDK 安装路径或新的命令行工具环境中执行任务时，需要把实测到的本机事实沉淀下来，供后续 Agent 复用，但不能污染共享 `.rules/` 或 `AGENTS.md` 的通用规则。

**自动触发条件（满足任意一条即应主动阅读本文件）**：
- 首次接触一台新机器、新工作区、新模拟器或新真机。
- 探测到 SDK、DevEco Studio、Hvigor、HDC/HDB、模拟器 target、构建命令、安装/启动命令与共享规则中的基线不同。
- 需要记录“本机可用命令”“本机不可用命令”“当前设备 target”“当前工具链路径”等事实。
- 用户要求检查、建立、修复或说明“本地规则库”。

---

## 1. 分层原则

- `.rules/`：共享技能规则库，只记录跨机器可复用的流程、约束、模式和已验证的通用命令形态。
- `.local-rules/`：本机规则库，只记录当前机器、当前用户、当前设备和当前工具链的事实与验证结果。
- `AGENTS.md`：统一入口，只写读取顺序、优先级和边界，不应持续堆积每台机器的真实路径。

本地事实可以覆盖共享规则中的“当前机器基线”，但不能覆盖共享规则中的架构原则、ArkTS 规范、安全约束、代码风格和规则更新边界。

---

## 2. 必读入口

进入陌生环境时，Agent 应按以下顺序读取：

1. `AGENTS.md`
2. `.rules/README.md`
3. 命中的 `.rules/skill-*.md`
4. `.local-rules/README.md`（如果存在）
5. `.local-rules/base-local-rules.md`（如果存在）
6. `.local-rules/*.local.md`（如果存在，按任务相关性选择读取）

如果 `.local-rules/` 不存在，Agent 可以创建基础索引文件；如果只缺少具体 `*.local.md` 文件，Agent 可以在完成探测后创建。

---

## 3. 可以写入本地规则库的内容

适合写入 `.local-rules/*.local.md`：

- 本机 DevEco Studio、HarmonyOS SDK、OpenHarmony SDK、Hvigor、HDC/HDB 的真实路径。
- 本机命令实测结果，例如版本号、成功命令、失败命令、失败原因。
- 当前可连接设备或模拟器 target，例如 `<device-target>`。
- 当前项目在本机生成的 HAP 路径、安装命令、启动命令、日志采集命令。
- 与本机环境有关的临时注意事项，例如某个路径权限拒绝、某个命令组合会超时。

不适合写入 `.local-rules/*.local.md`：

- ArkTS 语法规范、框架架构原则、UI 设计规范等跨机器规则。
- 只属于一次任务的业务决策、页面文案、临时补丁。
- 证书密码、密钥、token、账号、设备个人隐私、绝对私密路径中的敏感片段。
- 未验证的猜测。

---

## 4. 本地文件命名建议

建议按主题拆分，不要把所有内容写进一个大文件：

| 文件 | 用途 |
|------|------|
| `.local-rules/current-machine.local.md` | 本机 SDK、IDE、Hvigor、Node、Python 等基础环境事实 |
| `.local-rules/device-hdc.local.md` | HDC/HDB、模拟器/真机 target、安装/启动/日志命令实测结果 |
| `.local-rules/build-commands.local.md` | 本机可用构建命令、构建产物路径、失败命令和原因 |
| `.local-rules/known-issues.local.md` | 本机特有问题、绕过方式、仍需人工确认的事项 |

所有 `*.local.md` 默认视为本机私有文件，不应提交到共享仓库。

---

## 5. 写入格式

本地规则条目应短、准、可复验：

```markdown
## 2026-06-15 环境探测

**适用范围**：当前 Windows 用户 / 当前 NGF 工作区  
**探测命令**：`Test-Path '<本机 DevEco Studio SDK 根目录>'`  
**结果**：存在  
**结论**：当前构建优先使用该 SDK 根目录作为 `DEVECO_SDK_HOME`。  
**验证状态**：已实测  
```

禁止只写“可用”“不可用”而不写验证命令。禁止把共享 `.rules/` 的整段规范复制到本地文件。

---

## 6. 冲突处理

- 本地事实与共享规则冲突时，当前任务先使用本地实测事实。
- 如果冲突说明共享规则已经过期，但这个变化可跨机器复用，应在交付时提示开发者是否进入 `skill-rules-update.md` 流程。
- 如果冲突只属于本机安装位置、设备 target 或命令结果，不要修改 `.rules/` 或 `AGENTS.md`。
- 如果本地文件之间冲突，以最新有验证命令和验证日期的条目为准。

---

## 7. 安全边界

- 可以自动读取本地规则库。
- 可以在探测后自动写入 `*.local.md` 记录本机事实。
- 不得自动写入密钥、证书密码、token、账号、私有服务器地址等敏感信息。
- 不得因为本机缺少某个 SDK 就自动降级仓库 `targetSdkVersion` / `compatibleSdkVersion`。
- 不得因为本机路径不同就直接修改共享 `.rules/` 或 `AGENTS.md`。
