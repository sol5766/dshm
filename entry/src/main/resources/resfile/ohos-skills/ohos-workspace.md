# DSHM 工作区（认领 → 按路径直接读写 → 必要时发布）

## 链路
1. 每次启动 DSHM 用系统目录选择器的 DOWNLOAD 模式**无 UI 认领**本应用自己的用户可见目录
   `Download/<包名>/`（例：`/storage/Users/currentUser/Download/com.dshm.dshclient`），
   并把它的**绝对路径**经 `DSHM_PUBLIC_DOWNLOAD` 交给 Host。
2. Host 会校验：`lstat` 判为目录 **且** 能创建/写入/删除一个探测文件；
   两条都过 ⇒ 它就是默认工作区，新会话的 cwd 就是它。
3. **这个目录按路径直接读写**：node 子进程用普通文件系统路径 `open/write/read`
   打开它，不是 URI。

## 写文件：三步顺序（照做，不要跳步）
1. **优先直接写工作区**：用**相对路径**（相对会话 cwd，即工作区目录本身），或用**普通绝对路径**
   （`/storage/.../Download/<包名>/...`）。写进去就是成品——用户立刻能在"文件管理 → 下载"里看到。
2. **如果写不进**（认领失败、工作区已回退到沙箱、或写入被拒/报错），**就写到沙箱**
   `<files>/workspace/<相对路径>`：沙箱内一定可写，先把文件做出来。
3. **然后调用 `publish` 工具**把它复制到用户可见的 `Download/<包名>/`——
   `publish(source, target?)`：`source` 是沙箱里的路径（相对会话 cwd 或绝对路径），
   `target` 省略时按源的相对路径同形落位、目录不存在会自动建；
   最后**把 publish 返回的最终路径告诉用户**，那才是成品在哪。
4. **输出时只指明位置**：直接给出成品的路径（或工作区相对路径）即可；
   **不得**在回答里写"无需 publish""已跳过 publish""不用发布"这类**关于输出位置策略**的说明。

## 会话内其它约定
- 读写工作区文件一律用**路径**：相对路径（相对会话 cwd）或普通绝对路径。
- **不要用 `file://` URI**：URI 是目录选择器授权凭据的内部形态，node 子进程无法用它打开文件。
- 工作区回退到沙箱时，成品用户看不见——**分辨方法与必做动作**见下一节。
- 其它应用的目录（如 `/storage/.../Download/<别的包名>/`）由操作系统按包名归属拒绝，
  这是预期行为：报"无权限"，不要反复强试。

## 回退（唯一的例外，触发条件写清）
- **认领失败**（系统未授予/取消下载目录）或**该路径 lstat 非目录 / 探写不过**时，
  Host 会如实记录理由并回退到应用沙箱 `<files>/workspace`。此时工作区在沙箱内、用户不可见。
- 分辨方法只有一条：看会话 cwd / 启动日志里的 `默认工作区：…` 那行
  （`来源=DSHM_PUBLIC_DOWNLOAD` ⇒ 用户可见目录；`回退 …/files/workspace` ⇒ 沙箱）。
- 在沙箱工作区里做完的成品，**必须**再走上面第 3 步 `publish`，否则用户永远看不到它。

## 只读探查
- `ls /storage/media /storage/cloud` 等只读探查受权限限制可能报错——此时直接提示"无权限"，不要反复强试。
